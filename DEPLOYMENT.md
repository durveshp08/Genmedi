# Genmedi Deployment Guide

This guide explains how to deploy the Genmedi platform for production use with the following architecture:

- **Frontend**: Vercel (React + Vite)
- **Backend**: Render (Express.js + Node.js)
- **Database**: MongoDB Atlas
- **Repository**: GitHub

## Prerequisites

### 1. MongoDB Atlas Setup

1. **Create MongoDB Atlas Account**
   - Go to [MongoDB Atlas](https://www.mongodb.com/cloud/atlas)
   - Sign up for a free account

2. **Create a Cluster**
   - Create a new cluster (choose the free M0 tier for development)
   - Select a region closest to your users (e.g., Mumbai for India)

3. **Configure Database Access**
   - Go to "Database Access" → "Add New Database User"
   - Create a user with username and password
   - Set "Database User Privileges" to "Read and write to any database"

4. **Configure Network Access**
   - Go to "Network Access" → "Add IP Address"
   - For development: Add your current IP
   - For production: Add `0.0.0.0/0` (allow all IPs) or use VPC peering

5. **Get Connection String**
   - Go to "Database" → "Connect" → "Connect your application"
   - Copy the connection string
   - Replace `<password>` with your database user password
   - Format: `mongodb+srv://username:password@cluster.mongodb.net/genmedi?retryWrites=true&w=majority`

### 2. API Keys Setup

#### Gemini AI API Key
1. Go to [Google AI Studio](https://aistudio.google.com/app/apikey)
2. Create a new API key
3. Save it for backend configuration

#### Razorpay Keys (Optional - for payments)
1. Go to [Razorpay Dashboard](https://dashboard.razorpay.com/apikeys)
2. Generate Key ID and Key Secret
3. Save them for backend configuration

### 3. GitHub Repository

1. Initialize git repository (if not already done):
```bash
git init
git add .
git commit -m "Initial commit"
```

2. Create repository on GitHub
3. Push to GitHub:
```bash
git remote add origin https://github.com/your-username/genmedi.git
git branch -M main
git push -u origin main
```

## Deployment Steps

### Step 1: Deploy Backend to Render

1. **Create Render Account**
   - Go to [Render](https://render.com)
   - Sign up and connect your GitHub account

2. **Create Web Service**
   - Click "New +" → "Web Service"
   - Connect your GitHub repository
   - Select the `genmedi` repository
   - Render will automatically detect the `render.yaml` configuration

3. **Configure Environment Variables**
   Render will automatically configure most variables from `render.yaml`, but you need to set:
   
   - `DATABASE_URL`: Your MongoDB Atlas connection string
   - `FRONTEND_URL`: Your Vercel frontend URL (after deploying frontend)
   - `GEMINI_API_KEY`: Your Gemini AI API key
   - `RAZORPAY_KEY_ID`: Your Razorpay Key ID (optional)
   - `RAZORPAY_KEY_SECRET`: Your Razorpay Key Secret (optional)
   - `JWT_SECRET`: Auto-generated by Render (or set your own)
   - `JWT_REFRESH_SECRET`: Auto-generated by Render (or set your own)

4. **Deploy**
   - Click "Create Web Service"
   - Render will build and deploy your backend
   - Wait for deployment to complete (check the "Logs" tab)

5. **Get Backend URL**
   - Once deployed, copy the backend URL (e.g., `https://genmedi-api.onrender.com`)

### Step 2: Deploy Frontend to Vercel

1. **Create Vercel Account**
   - Go to [Vercel](https://vercel.com)
   - Sign up and connect your GitHub account

2. **Import Project**
   - Click "Add New Project"
   - Select your `genmedi` repository
   - Vercel will detect the `frontend` directory

3. **Configure Project**
   - **Root Directory**: `frontend`
   - **Framework Preset**: Vite
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`

4. **Configure Environment Variables**
   - Go to "Settings" → "Environment Variables"
   - Add:
     - `VITE_API_URL`: Your Render backend URL (e.g., `https://genmedi-api.onrender.com`)
     - `VITE_WS_URL`: Your backend WebSocket URL (e.g., `wss://genmedi-api.onrender.com/ws/tracking`)

5. **Deploy**
   - Click "Deploy"
   - Vercel will build and deploy your frontend
   - Wait for deployment to complete

6. **Get Frontend URL**
   - Once deployed, copy the frontend URL (e.g., `https://genmedi.vercel.app`)

### Step 3: Update Backend with Frontend URL

1. Go back to Render dashboard
2. Select your `genmedi-api` service
3. Go to "Environment" section
4. Update `FRONTEND_URL` with your Vercel frontend URL
5. Click "Save Changes" to trigger a redeploy

### Step 4: Seed Database (Optional)

If you need to seed the database with initial data:

1. Go to Render dashboard
2. Open your service's "Shell" (if available) or use Render's SSH
3. Run:
```bash
cd /opt/render/project/backend
npm run seed
```

Alternatively, you can seed locally by connecting to MongoDB Atlas:
```bash
cd backend
npm run seed
```

## Troubleshooting

### Backend Issues

**Problem**: Backend fails to start
- **Solution**: Check Render logs, verify DATABASE_URL is correct, ensure MongoDB Atlas is accessible

**Problem**: CORS errors
- **Solution**: Ensure FRONTEND_URL in backend matches your Vercel URL exactly

**Problem**: Database connection timeout
- **Solution**: Check MongoDB Atlas Network Access settings, ensure your IP is whitelisted

### Frontend Issues

**Problem**: Frontend can't connect to backend
- **Solution**: Verify VITE_API_URL is correct, check backend is running, verify CORS settings

**Problem**: Build fails
- **Solution**: Check Vercel build logs, ensure all dependencies are installed

### MongoDB Issues

**Problem**: Connection refused
- **Solution**: Verify connection string format, check username/password, ensure IP whitelist is correct

**Problem**: Authentication failed
- **Solution**: Verify database user credentials, ensure user has correct permissions

## Continuous Deployment

Both Vercel and Render support automatic deployments when you push to GitHub:

- **Vercel**: Automatically deploys on push to main branch
- **Render**: Automatically deploys on push to main branch

To enable:
1. Connect your GitHub repository to both platforms
2. Ensure your `render.yaml` and `vercel.json` are committed
3. Push changes to trigger automatic deployments

## Security Best Practices

1. **Never commit .env files** - They're in .gitignore
2. **Use strong secrets** - Generate 64+ character random strings for JWT secrets
3. **Rotate secrets regularly** - Update API keys and secrets periodically
4. **Enable HTTPS** - Both Vercel and Render provide automatic SSL
5. **Monitor logs** - Regularly check deployment logs for suspicious activity
6. **Use environment-specific configs** - Different configs for dev/staging/production

## Cost Estimation
